## 项目概述

### 项目需求
- **业务场景**：水位监测系统，多个监测站上报水位数据
- **核心功能**：
  - 监测站 CRUD 管理
  - 水位数据上报
  - 自动警报判断（超过阈值触发警报）
  - 历史数据查询
  - 警报处理

### 系统架构
```
前端 (HTML/CSS/JS) 
    ↓ HTTP
后端 (Spring Boot)
    ↓ MyBatis
数据库 (MariaDB)
```

## 详细开发步骤

### 第1步：数据库设计

**逻辑**：先设计数据结构，确定实体关系

```sql
-- 1. 站点表：存储监测站基本信息和阈值
CREATE TABLE station (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(64) NOT NULL,
    location VARCHAR(128),
    warn_level DECIMAL(6,2) NOT NULL,   -- 警戒水位
    danger_level DECIMAL(6,2) NOT NULL, -- 危险水位
    status TINYINT DEFAULT 1,           -- 1正常 0停用
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

-- 2. 水位记录表：存储每次上报的水位数据
CREATE TABLE water_record (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    station_id BIGINT NOT NULL,         -- 关联站点
    water_level DECIMAL(6,2) NOT NULL,  -- 水位值
    recorded_at DATETIME NOT NULL,      -- 采集时间
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 3. 警报记录表：存储触发的警报
CREATE TABLE alert_record (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    station_id BIGINT NOT NULL,
    record_id BIGINT NOT NULL,          -- 关联哪条水位记录
    alert_type TINYINT NOT NULL,        -- 1警戒 2危险
    water_level DECIMAL(6,2) NOT NULL,  -- 触发时的水位
    status TINYINT DEFAULT 0,           -- 0未处理 1已处理
    handled_at DATETIME,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

**设计要点**：
- 使用 `DECIMAL(6,2)` 存储水位，避免浮点误差
- 添加索引优化查询：`station_id`, `recorded_at`, `status`
- 软删除（status 字段）而非物理删除

### 第4步：DTO 和 VO

**逻辑**：分层设计，解耦数据传递

#### 4.1 DTO (Data Transfer Object) - 入参

```java
// WaterReportDTO.java - 水位上报入参
@Data
public class WaterReportDTO {
    @NotNull(message = "站点ID不能为空")
    private Long stationId;
    
    @NotNull(message = "水位值不能为空")
    @Positive(message = "水位值必须为正数")
    private BigDecimal waterLevel;
    
    private LocalDateTime recordedAt;  // 可选，默认当前时间
}
```

**DTO 作用**：
- 定义接口接收的参数
- 添加校验注解 (`@NotNull`, `@Positive`)
- 与数据库实体解耦

#### 4.2 VO (View Object) - 出参

```java
// StationVO.java - 返回给前端的数据
@Data
public class StationVO {
    private Long id;
    private String name;
    private String location;
    private BigDecimal warnLevel;
    private BigDecimal dangerLevel;
    private Integer status;
    private LocalDateTime createdAt;
    private LocalDateTime updatedAt;
}
```

**VO 作用**：
- 定义返回给前端的数据结构
- 可以组合多个实体字段
- 隐藏敏感字段

**为什么要分层**：
- POJO：与数据库表严格对应
- DTO：控制层接收参数，可添加校验
- VO：控制层返回数据，可按需定制

### 第5步：MyBatis Mapper

**逻辑**：定义数据库操作接口和 SQL

#### 5.1 Mapper 接口

```java
@Mapper  // 标记为 MyBatis Mapper
public interface StationMapper {
    
    List<Station> findAll();
    
    Station findById(Long id);
    
    // useGeneratedKeys：返回自动生成的主键
    // keyProperty：主键赋值给哪个属性
    int insert(Station station);
    
    int update(Station station);
}
```

#### 5.2 Mapper XML

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN" 
    "http://mybatis.org/dtd/mybatis-3-mapper.dtd">

<mapper namespace="com.example.watermonitor.mapper.StationMapper">
    
    <!-- 查询所有正常状态的站点 -->
    <select id="findAll" resultType="com.example.watermonitor.model.pojo.Station">
        SELECT * FROM station WHERE status = 1 ORDER BY id
    </select>
    
    <!-- 根据ID查询 -->
    <select id="findById" resultType="com.example.watermonitor.model.pojo.Station">
        SELECT * FROM station WHERE id = #{id}
    </select>
    
    <!-- 插入：useGeneratedKeys 获取自增主键 -->
    <insert id="insert" useGeneratedKeys="true" keyProperty="id">
        INSERT INTO station (name, location, warn_level, danger_level, status)
        VALUES (#{name}, #{location}, #{warnLevel}, #{dangerLevel}, #{status})
    </insert>
    
    <!-- 动态更新：只更新非空字段 -->
    <update id="update">
        UPDATE station
        <set>
            <if test="name != null">name = #{name},</if>
            <if test="location != null">location = #{location},</if>
            <if test="warnLevel != null">warn_level = #{warnLevel},</if>
            <if test="dangerLevel != null">danger_level = #{dangerLevel},</if>
            <if test="status != null">status = #{status}</if>
        </set>
        WHERE id = #{id}
    </update>
    
</mapper>
```

**关键技术点**：
- `useGeneratedKeys="true"`：插入后获取自增 ID
- `<if>` 标签：动态 SQL，实现选择性更新
- `#{}`：预编译参数，防止 SQL 注入

### 第6步：DAO 层

**逻辑**：封装数据库访问，对外提供简洁接口

```java
@Repository  // Spring 数据访问层标记
public class StationDao {
    
    @Autowired
    private StationMapper stationMapper;
    
    public List<Station> findAll() {
        return stationMapper.findAll();
    }
    
    public Station findById(Long id) {
        return stationMapper.findById(id);
    }
    
    public int save(Station station) {
        station.setStatus(1);  // 默认正常状态
        return stationMapper.insert(station);
    }
    
    public int update(Station station) {
        return stationMapper.update(station);
    }
    
    public int disable(Long id) {
        Station station = new Station();
        station.setId(id);
        station.setStatus(0);  // 软删除
        return stationMapper.update(station);
    }
}
```

**DAO vs Mapper**：
- Mapper：直接对应 SQL 操作
- DAO：业务层面的数据访问，可组合多个 Mapper 操作

### 第7步：Service 层（核心业务）

**逻辑**：实现业务逻辑，事务管理

```java
@Service  // 标记为服务层
public class WaterRecordService {
    
    @Autowired
    private WaterRecordDao waterRecordDao;
    
    @Autowired
    private StationDao stationDao;
    
    @Autowired
    private AlertRecordDao alertRecordDao;
    
    // @Transactional：事务注解，保证数据一致性
    @Transactional
    public void reportWaterLevel(WaterReportDTO dto) {
        // 1. 校验站点
        Station station = stationDao.findById(dto.getStationId());
        if (station == null) {
            throw new RuntimeException("监测站不存在");
        }
        if (station.getStatus() != 1) {
            throw new RuntimeException("监测站已停用");
        }
        
        // 2. 保存水位记录
        WaterRecord record = new WaterRecord();
        record.setStationId(dto.getStationId());
        record.setWaterLevel(dto.getWaterLevel());
        record.setRecordedAt(dto.getRecordedAt() != null 
            ? dto.getRecordedAt() : LocalDateTime.now());
        waterRecordDao.save(record);
        
        // 3. 判断警报
        BigDecimal level = dto.getWaterLevel();
        BigDecimal danger = station.getDangerLevel();
        BigDecimal warn = station.getWarnLevel();
        
        AlertRecord alert = null;
        
        if (level.compareTo(danger) >= 0) {
            // 危险警报
            alert = createAlert(station, record, AlertType.DANGER, level);
        } else if (level.compareTo(warn) >= 0) {
            // 警戒警报
            alert = createAlert(station, record, AlertType.WARNING, level);
        }
        
        // 4. 保存警报（如果有）
        if (alert != null) {
            alertRecordDao.save(alert);
        }
    }
    
    private AlertRecord createAlert(Station station, WaterRecord record, 
                                    AlertType type, BigDecimal level) {
        AlertRecord alert = new AlertRecord();
        alert.setStationId(station.getId());
        alert.setRecordId(record.getId());
        alert.setAlertType(type.getCode());
        alert.setWaterLevel(level);
        alert.setStatus(0);  // 未处理
        return alert;
    }
}
```

**关键逻辑解析**：

1. **事务管理**：`@Transactional`
   - 确保「保存水位」和「创建警报」要么都成功，要么都失败
   - 避免数据不一致

2. **警报判断逻辑**：
   ```
   if (水位 >= 危险阈值) → 危险警报
   else if (水位 >= 警戒阈值) → 警戒警报
   else → 正常，无警报
   ```

3. **BigDecimal 比较**：
   - `compareTo()` 方法比较大小
   - 不能用 `==` 或 `equals()`

### 第8步：Controller 层 (API)

**逻辑**：接收 HTTP 请求，调用 Service，返回统一格式

```java
@RestController  // = @Controller + @ResponseBody
@RequestMapping("/stations")  // 基础路径
public class StationController {
    
    @Autowired
    private StationService stationService;
    
    // GET /stations
    @GetMapping
    public Result<List<StationVO>> getAllStations() {
        List<Station> stations = stationService.getAllStations();
        
        // POJO → VO 转换
        List<StationVO> voList = stations.stream()
            .map(this::convertToVO)
            .collect(Collectors.toList());
        
        return Result.success(voList);
    }
    
    // GET /stations/{id}
    @GetMapping("/{id}")
    public Result<StationVO> getStationById(@PathVariable Long id) {
        Station station = stationService.getStationById(id);
        if (station == null) {
            return Result.error("站点不存在");
        }
        return Result.success(convertToVO(station));
    }
    
    // POST /stations
    @PostMapping
    public Result<Void> addStation(@RequestBody Station station) {
        stationService.addStation(station);
        return Result.success();
    }
    
    // PUT /stations/{id}
    @PutMapping("/{id}")
    public Result<Void> updateStation(@PathVariable Long id, 
                                      @RequestBody Station station) {
        station.setId(id);
        stationService.updateStation(station);
        return Result.success();
    }
    
    // DELETE /stations/{id}
    @DeleteMapping("/{id}")
    public Result<Void> deleteStation(@PathVariable Long id) {
        stationService.disableStation(id);
        return Result.success();
    }
    
    // POJO 转 VO
    private StationVO convertToVO(Station station) {
        StationVO vo = new StationVO();
        BeanUtils.copyProperties(station, vo);  // 属性复制
        return vo;
    }
}
```

**注解说明**：

| 注解 | 作用 |
|------|------|
| `@RestController` | 声明 REST API 控制器 |
| `@RequestMapping` | 基础路径映射 |
| `@GetMapping` | 处理 GET 请求 |
| `@PostMapping` | 处理 POST 请求 |
| `@PutMapping` | 处理 PUT 请求 |
| `@DeleteMapping` | 处理 DELETE 请求 |
| `@PathVariable` | 获取 URL 路径参数 |
| `@RequestBody` | 获取请求体 JSON |

### 第9步：公共类

#### 9.1 统一返回结果

```java
@Data
public class Result<T> {
    private int code;       // 200成功，500错误
    private String message;
    private T data;
    
    public static <T> Result<T> success(T data) {
        Result<T> r = new Result<>();
        r.setCode(200);
        r.setMessage("success");
        r.setData(data);
        return r;
    }
    
    public static <T> Result<T> error(String message) {
        Result<T> r = new Result<>();
        r.setCode(500);
        r.setMessage(message);
        return r;
    }
}
```

**为什么要统一返回**：
- 前端处理方便
- 接口风格一致
- 错误信息标准化

#### 9.2 全局异常处理

```java
@RestControllerAdvice  // 全局异常处理器
public class GlobalExceptionHandler {
    
    // 处理业务异常
    @ExceptionHandler(RuntimeException.class)
    public Result<Void> handleRuntimeException(RuntimeException e) {
        return Result.error(e.getMessage());
    }
    
    // 处理参数校验异常
    @ExceptionHandler(BindException.class)
    public Result<Void> handleBindException(BindException e) {
        String message = e.getFieldErrors().stream()
            .map(FieldError::getDefaultMessage)
            .collect(Collectors.joining(", "));
        return Result.error(400, message);
    }
}
```

**作用**：
- 统一异常处理，不用在每个接口 try-catch
- 参数校验失败自动返回友好的错误信息

## 关键技术点解析

### 1. 分层架构

```
Controller (控制层)
    ↓ 调用
Service (业务层) - 核心业务逻辑、事务
    ↓ 调用
DAO (数据访问层) - 封装数据库操作
    ↓ 调用
Mapper (映射层) - SQL 定义
    ↓
数据库
```

**为什么要分层**：
- 职责分离
- 便于测试
- 易于维护
- 可替换实现（如换数据库只需改 Mapper）

### 2. 事务管理

```java
@Transactional
public void reportWaterLevel(WaterReportDTO dto) {
    // 1. 保存水位
    waterRecordDao.save(record);
    
    // 2. 创建警报
    alertRecordDao.save(alert);
    // 如果这里抛出异常，步骤1会自动回滚
}
```

### 3. 数据流向

```
前端请求 → Controller → Service → DAO → Mapper → SQL → 数据库
前端 ← JSON ← Controller ← Service ← DAO ← Mapper ← 结果集
```

### 4. 参数校验

```java
public Result<Void> report(@Valid @RequestBody WaterReportDTO dto)
                              // ↑ @Valid 触发校验
```

- `@NotNull`：不能为空
- `@Positive`：必须为正数
- 校验失败自动返回 400 错误

## 遇到的问题与解决方案

### 问题1：Lombok 注解不生效

**现象**：编译报错，找不到 getter/setter 方法

**原因**：Maven 编译器插件未配置 Lombok 注解处理器

**解决**：
```xml
<plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-compiler-plugin</artifactId>
    <version>3.13.0</version>
    <configuration>
        <annotationProcessorPaths>
            <path>
                <groupId>org.projectlombok</groupId>
                <artifactId>lombok</artifactId>
                <version>1.18.32</version>
            </path>
        </annotationProcessorPaths>
    </configuration>
</plugin>
```

### 问题2：Spring Boot 3.x 包名变更

**现象**：`javax.validation.constraints` 不存在

**原因**：Spring Boot 3.x 使用 Jakarta EE 替代 Java EE

**解决**：
```java
// 旧（Spring Boot 2.x）
import javax.validation.constraints.NotNull;

// 新（Spring Boot 3.x）
import jakarta.validation.constraints.NotNull;
```

### 问题3：数据库连接失败

**现象**：`Access denied for user 'root'@'localhost'`

**解决**：
1. 检查 `application.yml` 中的密码是否正确
2. 确保 MariaDB 已启动
3. 数据库 `water_monitor` 已创建
